# 03 小程序：规则与开发运营攻略

> 官方依据：《微信小程序平台运营规范》《微信小程序平台常见拒绝情形》《小程序备案操作指引》

## 一、平台定位与价值观

官方定位：小程序是"在微信内搭建和实现特定服务、功能的平台"，价值观四条：

- 一切以用户价值为依归
- 让创造发挥价值
- **好的产品是用完即走**
- 让商业化存在于无形之中

这四句话不是口号，审核时经常被引用。比如"无实质服务内容，只是导流/下载 App"会被下架，就是违背"用完即走"。

## 二、从注册到上线：完整流程

```text
注册账号（邮箱/主体/管理员）
   → 填写基本信息（名称/头像/简介/服务范围/标签）
   → 选择并申请服务类目（部分类目需资质/定向准入）
   → 开发 + 配置服务器域名 + 隐私协议
   → 小程序 ICP 备案（2023-09-01 起强制）
   → 提交代码审核
   → 发布上线
   → 运营合规（内容安全/分享/支付/数据）
```

### 2.1 注册规范（2.1）

- 提供用户可联系到开发者的链接或邮箱；提供真实有效的小程序管理员微信号。
- 🔴 不得关联至你不具有完整合法权益或授权的网站、应用、产品、服务。
- 🔴 不允许重复注册、提交 2 个及以上页面/内容/功能相同或同质化严重的小程序。
- 平台可在提交和运营全过程要求补充材料，不配合会影响审核结果。

### 2.2 基本信息规范（2.2）

- 名称/logo/简介要准确描述功能，三者相互关联，符合用户对实际服务的预期。
- 🔴 不得含政治敏感、色情、暴力血腥、恐怖及违法内容。
- 🔴 不得混有商业化用语、热门公众号/小程序/应用名称、流行语、"国家级""最高级"等广告法禁止用语、水印标识。
- 🔴 未经授权不得使用第三方商标/品牌标识或近似标识。
- 🔴 无正当理由不得与已有小程序/公众号/热门应用名称重复或混淆；不得用广义归纳类、无识别性词汇、热门搜索词堆砌对抗搜索规则。
- 🔴 注册明星粉丝团/后援会须经纪公司授权。

### 2.3 功能设置规范（2.3）

- 实际服务与简介一致，**不存在隐藏类目**；核心功能必须在首页体现。
- 需提供功能指引（描述或截图）。
- 服务范围与实际类目、标签一致，不超类目库范围。
- 🔴 **一旦选择游戏类目，不可变更为其他小程序类目。**
- 功能不能过于简单，不得与其他小程序同质化严重（常见驳回：只有一个页面一个按钮）。
- 🔴 未经授权不得提供与微信客户端相同或相似的功能（如朋友圈、漂流瓶）。
- 🔴 未经授权，小程序使用不得以使用其他小程序/App 为条件，也不得展示推荐其他小程序或公众号（不能做小程序导航、互推、排行榜）。
- 应设置侵权投诉机制；对未成年人不宜内容做提醒或处理；不得把人的外貌/身份/能力商品化展示（如纯美女图册）。
- 须如实充分披露活动规则、产品条件、机构品牌信息、权利义务、投诉渠道。

### 2.4 主体规范（2.4）

- 主体需符合法律法规；按要求提供审批/备案资质，材料必须真实合法有效。
- 伪造材料 → 拒绝或强制措施，并保留追责权利。
- 为违法活动提供便利协助 → 拒绝。
- 无许可从事需许可经营 → 拒绝。

## 三、ICP 备案：硬性前置条件

- 依据《互联网信息服务管理办法》，自 **2023-09-01** 起所有小程序都需完成备案；**2023-09-04** 起未上架小程序须完成备案才可上架。
- 每个小程序需**独立备案**，不能拿其他小程序或网站的备案替代。
- 备案入口：小程序管理后台首页「去备案」或「设置 → 小程序备案」。
- 备案不收费；备案号在小程序发布后自动展示在"更多资料页"，无需自行展示。
- 流程五步：填写备案信息 → 微信平台初审 → 工信部短信核验 → 通信管理局审核 → 备案成功。
- 时效参考（官方社区 QA）：平台初审一般 1–2 个工作日；初审驳回后重提一般按 7 个工作日；管局审核 1–20 个工作日；不支持加急。
- 短信核验：来自 12381 开头短信，**24 小时内**完成，填验证码+负责人手机号+证件号后 6 位。
- 前置审批：新闻、出版、游戏、网络视听、药品和医疗器械、网约车等需提供对应前置审批文件。
- 🔴 **变更备案**：名称、负责人、主体名称、主体负责人、联系方式变化都要及时发起变更；主体统一社会信用代码变更需先注销原备案再重新备案。未及时变更或注销，平台可警告、封禁功能、强制注销备案（运营规范 2.5.35）。

## 四、审核驳回高频原因（官方《常见拒绝情形》）

### 4.1 账号基本信息

- 名称、简介、logo、服务范围、服务标签含侵权内容、商业化用语、热门名称、"国家级/最高级"、政治色情敏感暴力恐怖词汇。
- 简介需明确介绍功能点，不能用"提高生活品味""提高购物体验"这类模糊表达。
- 名称与简介语义要一致，与实际功能一致，不含无关搜索热词。
- 名称不能以电话、邮件、日历、小游戏等广义归纳类词、斗地主/麻将等通用游戏名、其他不具识别性词命名；名称一般需两个词以上组合。
- logo 清晰度不足、与名称简介不一致、含腾讯/微信官方品牌标识 → 驳回。
- 服务标签不能超出服务范围（如服务范围是家政、标签是美食）。

### 4.2 服务类目

- 类目要与小程序提供的服务一致；核心内容必须与类目一致。
- 用户在该页面能用该类目服务，不得隐藏、不得多次跳转才能到达。
- 类目对应页面链接不能打不开、加载非法信息、恶意色情广告、侵权内容。

### 4.3 整体审核

- 实际功能点需与简介一致。
- 所有服务类目功能必须在首页体现，即首页可直达或 2 次点击内到达所有类目页面。
- 不得超出已开放类目库（如游戏尚未开放时不可做）。
- 隐藏/付费功能不得含违规内容，提审测试号需可完整体验。
- 功能应有使用价值，不能过于简单（只有一个页面、一个按钮）。
- 未经授权不得提供与微信客户端相同/类似功能。
- 未经允许不得展示推荐第三方小程序（导航、互推、排行榜）。
- 功能使用不得以关注或使用其他号为条件。

### 4.4 可用性与完整性

- 页面只有 title 和底部 button，中间无运营内容；"无任何商品""加载完了"、空白页 → 驳回。
- 一直"加载中"/"无法加载"、白屏。
- 功能报错：获取用户信息失败、无法打开业务域名、网络异常、请求/验签失败。
- 主业务控件无响应。
- 用官方 demo 提审（hello world、组件示例图）、上传测试数据（"测试商品/测试版块/测试服务"）。
- 需特定账号密码、注册流程不开放、测试环境/内部鉴权/需绑定蓝牙或地理位置，但未提供有效测试账号和操作路径。

✅ **提审前自查清单**：功能完整可跑通 → 首页直达所有类目 → 测试账号可用 → 无测试数据/demo → 域名配置正确 → 隐私协议与授权弹窗齐全 → 备案已完成 → 类目资质齐全 → 无隐藏功能。

## 五、37 类行为规范：按风险归类

官方运营规范 2.5 列出 2.5.1–2.5.37，下面按实际风险归类速查。

### 5.1 分享与营销类

| 条款 | 行为 | 要点 | 处罚 |
|---|---|---|---|

| 2.5.10 | 互推 | 推荐推广排行其他小程序/小游戏/App，或集中设立跳转添加平台 | 下架 |

### 5.2 数据与隐私类（2.5.12）

🔴 重点条款：采集前须用户同意并如实披露用途范围；不得窃取密码和个人数据；不得要求输入个人信息才可用功能（除法律要求或用户同意）；用户要求删除时应删除，终止使用时立即删除；不得向其他用户或第三方显示微信号/手机号等；不得用于未授权用途；不得反射查找跟踪挖掘；不得通过上传照片或人像识别恶意搜集隐私（**包括人像评分、AI 算命**）；不得过度收集、数据滥用、未授权共享转让、不履行安全保护义务；不得抓取微信账号/关系链/好友列表/银行账号等敏感数据。

处罚：封禁相应能力直至封号。

## 六、处罚体系

```text
风险提醒 → 限期整改 → 删除内容/清空违规信息 → 限制单项能力
→ 限制分享/被搜索/支付/二维码 → 结果禁搜 → 封禁功能
→ 下架 → 封号 → 拒绝向主体及关联主体提供服务
```

🔴 **主体关联**：同一主体及关联主体下小程序对抗行为超过 1 次（≥2），按同一阶梯累计处罚。

## 七、投诉与申诉

- 官方运营规范第四章"投诉与处罚规范"：用户投诉入口在小程序内及微信客户端；开发者收到违规通知后按提示整改或申诉。
- 审核驳回：在小程序管理后台查看驳回原因，修改后重新提交；有疑问可在微信开放社区发帖附 AppID 和截图。
- 备案问题：小程序后台「设置 → 小程序备案」查看进度；管局审核期间保持负责人手机畅通。

## 八、开发运营实操建议（非官方条款）

### 8.1 提审前 15 项自检

- [ ] 备案已完成，备案信息与实际信息一致
- [ ] 服务类目已申请通过，且首页 2 次点击内可达所有类目
- [ ] 名称/头像/简介三者语义一致，无商业化用语和热门词堆砌
- [ ] 功能与简介一致，非 demo、非测试数据
- [ ] 测试账号可用，权限完整，无内部鉴权/地域限制
- [ ] 业务域名、服务器域名、下载域名配置正确
- [ ] 隐私协议、用户授权弹窗齐全，按最小必要收集信息
- [ ] UGC 功能已接入内容安全检测接口
- [ ] 分享无"分享后解锁/集赞/助力/概率奖励"，组队人数 ≤5
- [ ] 无诱导下载 App、无展示推荐其他小程序
- [ ] 虚拟商品走小程序虚拟支付，iOS 端无外部支付引导
- [ ] 支付完成页无无关营销跳转
- [ ] 无自动弹窗广告打断核心流程
- [ ] 提审版本与线上版本一致，无按 IP/地域/人群差异化展示
- [ ] 有特殊行业资质（医疗、金融、出版、网约车等）已上传有效文件

### 8.2 常见"以为没事其实违规"的点

- "用户自愿分享换积分" —— 仍属利诱分享、分享频率限制对象。
- "我们的算命是娱乐测试" —— 昵称测试/算命类属于内容安全重点监管场景；AI 算命明确列为恶意搜集隐私。
- "把支付放到 H5 更方便" —— 小程序内虚拟商品必须走虚拟支付。
- "审核时隐藏付费功能" —— 属于隐藏类目/规避审核，处罚很重。
- "多开几个马甲小程序导流" —— 同质化注册 + 互推 + 关联主体累计处罚。
